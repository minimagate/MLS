# M1 independent review

Scope: M1 parser CLI and applicable cross-cutting requirements from `docs/spec.md`.
Reviewer does not implement production code. Final code review is approved for
M1 after candidate 5; the parent owns milestone integration and native-editor checks.

## Acceptance evidence

- [x] Native TeXmacs parsing accepts short and long tags, nested environments,
  arguments, escaped delimiters, Unicode, and actual fixture documents.
- [x] Parsing/writing preserves existing document bytes except deliberate ID
  insertions; malformed input returns useful errors rather than silent truncation.
- [x] Every extracted block receives a unique ID stored in the document; reopening,
  editing source, and moving persisted blocks retain IDs. Duplicate/invalid metadata
  cannot silently create ambiguous block identity.
- [x] Tagged environment kinds, labels, and deterministic explicit references are
  extracted correctly, including nested formatting and forward references.
- [x] Duplicate labels and missing references have explicit, documented behavior;
  dependency IDs identify the intended blocks without invented edges.
- [x] Source hashes reflect source changes and exclude identity metadata as designed.
- [x] CLI emits inspectable blocks and diagnostics, reads without mutation by default,
  persists IDs only on its documented write option, and reports I/O/parse failures.
- [x] Relevant modules have unit tests. Property tests exercise ID invariants under
  source edits, moves, and reopen. Real `.tm` fixtures and checked-in expected block
  trees support golden tests. CLI integration tests execute the binary.
- [x] `make test` (or documented equivalent), formatting, and warnings-as-errors
  lint pass independently; default tests require neither network nor model keys.
- [x] README explains actual build/run/test behavior and limits; decisions and
  milestone checklist reflect implemented behavior and unresolved limitations.

## Adversarial cases

Empty and Unicode documents; literal escaped `<`, `>`, `|`, and backslash; tag-like
text; comments/preamble/metadata; mismatched long-tag names; missing delimiters;
trailing content; nested theorem/proof environments; formatting around labels and
references; references before declarations; multiple labels/references; self refs;
cycles; duplicate labels; missing labels; duplicate/invalid IDs; inserted unrelated
blocks; movement between sections; complete body replacement after persistence;
repeated write/reopen without churn; CLI parse error must preserve original bytes.

## Findings and result

See candidate history below and final approval at the end.

Additional persistence checks: unique temporary file creation (`create_new` or
an equivalent safe API), cleanup on every failure path, detection of source changes
between read and replacement, and preservation on source errors. Body extraction
must not treat preamble or metadata as live blocks when `<body>` is absent.

## Candidate 1 — changes required

Independent validation: `CARGO_HOME="$PWD/.cargo-home" make test` passes all
13 tests (2 CLI, 2 core, 8 parser/writer, 1 fixture), formatting and Clippy.
Default Cargo home could not resolve crates.io; the repository-local dependency
cache succeeds. Passing tests do not cover the following observed failures.

1. **P1 — source corruption when annotating ordinary formatted prose.**
   `crates/mls-tm/src/lib.rs::collect_candidates` recursively classifies text in
   every unknown tag argument as commentary. CLI input
   `<\body>Let <with|font-series|bold|x> be real. By <reference|def:x>.<\definition>X<label|def:x></definition></body>`
   emits separate commentary blocks for `font-series`, `bold`, `x`, `def:x`, and
   surrounding fragments; the prose has no dependency. `--write-ids` therefore
   inserts compound metadata inside formatting variable names and reference
   targets. Paragraphs must include inline tags, and tag control arguments must
   never become rendered text blocks.
2. **P1 — header/preamble mutation when body is absent.**
   `analyze` falls back to all document nodes. CLI input
   `<TeXmacs|2.1.4><style|generic><initial|<collection|<associate|theorem|not body>>>`
   reports `2.1.4` and `generic` as commentary. Writing annotates header/style
   arguments. Full native documents with no body must safely fail or yield no
   blocks; fragment support must be explicit and distinguish preamble metadata.
3. **P1 — writer can overwrite newer document content and unrelated temp files.**
   `crates/mls-tm/src/writer.rs::write_ids_atomic` never checks current file bytes
   against the analyzed `source`; uses predictable PID-named `fs::write` which
   truncates an existing temp file/follows a symlink; does not clean up if setting
   permissions fails. Use exclusive temp creation with managed cleanup and reject
   stale source before replacement. Add meaningful failure-path tests.
4. **P2 — invalid and multi-binding identity metadata is not handled.**
   `<with|mls-id|broken|<theorem|A>>` emits `mls-id` and `broken` as commentary
   without a diagnostic. `<with|font-series|bold|mls-id|11111111-1111-4111-8111-111111111111|<theorem|A>>`
   ignores the existing ID. Parse every variable/value pair, diagnose invalid
   metadata, and avoid annotating control fields. Preserve mathematical formatting
   when normalizing hashes (do not discard a whole multi-binding wrapper).
5. **P2 — native unnumbered environments lose their kind.**
   `<\body><theorem*|A><lemma*|B><proof*|P></body>` emits only commentary. Recognize
   native starred theorem-family variants that exist in TeXmacs and test them.
6. **P2 — explicit references can be dropped.**
   A block with `<label|a><label|b>` records only `a`; a reference to `b` becomes
   unresolved although it has a target. `collect_links` also starts with only
   `node.children()` for recognized blocks, dropping earlier arguments. Preserve
   aliases for resolution (even if the public model retains one primary label),
   or diagnose a documented restriction rather than silently dropping anchors.
7. **P2 — required golden corpus/coverage is missing.**
   `crates/mls-tm/tests/golden.rs` uses only a short fabricated document and inline
   kind assertions. There are no checked-in expected outputs or real TeXmacs
   fixture corpus. Tests also omit duplicate IDs/labels, unresolved/forward refs,
   metadata, formatted paragraphs, invalid IDs, write failures, and exact source
   preservation. The preservation test only proves original bytes occur as a
   subsequence, not that only the intended wrappers were added.

README has duplicated title and must document paragraph/fragment behavior and
identity lifetime accurately after fixes. The parser continuation unit test checks
only top-level span/name, not the argument tree, so it cannot prove native argument
semantics. Candidate is **not approved** until fixes and relevant regression tests
pass independent re-review.

## Candidate 2 — changes required

Independent `CARGO_HOME="$PWD/.cargo-home" make test` passes 20 tests. Header
safety, formatted inline control arguments, starred theorem variants, recognized
block aliases, native continuation arity, exclusive temporary creation, stale
source rejection, and exact insertion assertion have improved. Real licensed
TeXmacs fixtures and checked-in expected JSON now exist.

Remaining observed failures:

- **P1 — duplicate-ID repair never converges.** For a body containing two
  `<with|mls-id|11111111-1111-4111-8111-111111111111|<theorem|A>>` / `B` blocks,
  three successive `mls --write-ids` calls produce block counts 2, 3, 3; the extra
  commentary UUID changes on every call, `duplicate_id` remains, and new wrappers
  are inserted each time. `collect_body_prose` mistakes a nested ID carrier for
  prose because its recognized-child check only looks one level deep.
- **P2 — overlapping phantom commentary.**
  `<\body><with|color|red|<theorem|A<label|a>>></body>` emits both theorem and
  commentary covering its formatting wrapper. A formatting wrapper is not an
  independent prose claim; classify rendered paragraphs/blocks coherently.
- **P2 — paragraph identity and order are lost.**
  `<\body>First paragraph.\n\nSecond paragraph.</body>` is one block, so moving
  either paragraph cannot retain separate identities. The two-pass extraction
  emits tagged blocks before all prose regardless of source location.
- **P2 — prose aliases remain unresolved.**
  `<\body>text<label|a><label|b><theorem|By <reference|b>></body>` reports an
  unresolved reference to `b` although the prose contains that label.
- **P2 — multi-binding hash normalization still discards non-ID formatting.**
  `collect_carrier_ranges` removes the complete prefix/suffix of a `with` carrier
  whenever any binding is `mls-id`, rather than only identity metadata. A parent
  block's hash can therefore ignore source edits to other bindings.

Golden sampling: `texmacs-man-environments.en.expected.json` has correct theorem
spans 534–720 and 1178–1299 and proof 724–796. Its commentary entries combine the
native title and introductory paragraph, then several later native paragraphs.
This reflects the current extraction weakness and must be corrected rather than
regenerating expectations without checking semantic block boundaries. Require
regression coverage for duplicate repair/repeated reopen, wrapper nesting,
paragraph edits/moves, prose aliases, and multi-binding hashes before approval.

## Candidate 3 — changes required

Normal standalone paragraphs now have separate IDs in source order. Formatted-only
theorems no longer create phantom commentary, and prose aliases resolve. CLI safely
refuses invalid/duplicate identity writes, an acceptable conservative documented
alternative to automatic repair. Writer has additional no-op, permission, symlink,
invalid-span and cleanup tests. Previous temporary-file and source mutation
findings are resolved at the intended prototype scope.

One critical edit invariant remains broken: starting with
`<\body><\with|mls-id|11111111-1111-4111-8111-111111111111>First.\n\nSecond.</with></body>`
models splitting an already-persisted paragraph. Across three `--write-ids` calls,
First retains its UUID, but Second receives three different UUIDs and its source
acquires a new nested carrier on every call. The existing nested carrier is treated
as fresh unowned prose. **P1:** recursively honor existing prose carriers when
splitting their surrounding owner; prove convergent persistence after edits.

**P2:** `<\body><\with|color|red>Intro.\n\n<theorem|A>\n\nAfter.</with></body>`
emits only the theorem, silently omitting both rendered prose paragraphs because
`contains_formal_block` suppresses the entire outer container. Traverse rendered
container content for both formal and prose blocks without assigning control args.


## Candidate 5 — approved for M1

Independent final command `CARGO_HOME="$PWD/.cargo-home" make test` succeeds:
format check, Clippy with warnings denied, and 34 tests (3 CLI, 2 core,
25 parser/writer, 2 persistence, 2 golden). Reviewed CRLF and whitespace-only
paragraph separators and README's explicit invalid/duplicate-ID write refusal.

Independently ran the CLI three times with `--write-ids` for each of: ordinary
paragraphs, a formatted theorem, a formatted container mixing prose/theorem/prose,
prose label aliases, splitting an already persisted prose paragraph, forward plus
missing references, and duplicate labels. IDs, kinds, dependencies and diagnostics
remain stable; writes two and three leave source bytes identical. Duplicate-ID
input fails without changing the file. All previously reported review findings
are resolved, including safe refusal where automatic identity repair was unsafe.

Manually sampled the checked-in environments golden against original source:
title 93–119, introductory paragraph 123–530, theorem 534–720, proof 724–796,
next paragraph 800–1174, theorem 1178–1299, following paragraph 1303–1739. Entries
now respect source order and actual paragraph boundaries rather than the earlier
merged outputs. Full fixture comparisons and persistence checks pass.
